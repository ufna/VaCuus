## 1. Constructing `FScriptArrayHelper`; the API surface

**The pointer is the VALUE pointer, not the container.** The public ctor is `FScriptArrayHelper(const FArrayProperty* InProperty, const void* InArray)` (`Runtime/CoreUObject/Public/UObject/UnrealType.h:4285-4288`); its doc comment says `InArray` is "pointer to raw memory that corresponds to this array. This can be NULL, and sometimes is, but in that case almost all operations will crash" (`UnrealType.h:4280-4284`). It delegates to the private ctor passing `InProperty->Inner`, `Inner->GetElementSize()`, `Inner->GetMinAlignment()`, `InProperty->ArrayFlags` (`:4286`). The container-pointer convenience is `FScriptArrayHelper_InContainer(InProperty, InContainer, FixedArrayIndex=0)`, which applies `InProperty->ContainerPtrToValuePtr<void>(InContainer, FixedArrayIndex)` first (`UnrealType.h:4651-4663`).

**`CreateHelperFormInnerProperty` exists in 5.8.1, with that exact typo**: `static FScriptArrayHelper CreateHelperFormInnerProperty(const FProperty* InInnerProperty, const void* InArray, EArrayPropertyFlags InArrayFlags = EArrayPropertyFlags::None)` (`UnrealType.h:4537-4540`) — builds a helper from just the inner property + a raw `FScriptArray*`, for when you have no `FArrayProperty` (e.g. a channel slot that is a bare `FScriptArray`). It calls the same private ctor.

**Const-correctness: there is no const access path.** `GetRawPtr(int32 Index=0)` (`UnrealType.h:4324-4333`) and `GetElementPtr` (`:4340-4343`) are non-const member functions returning `uint8*`, with no const overloads (contrast `FScriptSetHelper`, which has const `GetElementPtr` at `:5887-5890`). Constness is laundered at construction: the private ctor const-casts, with the engine's own comment `//@todo, we are casting away the const here` (`UnrealType.h:4549-4557`). So for a read-only diff over two const shadows you construct two non-const helpers over `const void*` and promise not to mutate. `GetRawPtr` returns **NULL when the array is empty** and `checkSlow`s the index otherwise (`:4326-4331`).

**Mutation API, what each initializes/destroys** (all `UnrealType.h`):

| Call | Lines | Semantics |
|---|---|---|
| `Num()` / `NumUnchecked()` | 4303-4308 / 4314-4318 | element count; Unchecked skips the `checkSlow` (needed for intrusive-optional unset state) |
| `AddValues(Count)` | 4409-4414 | `AddUninitializedValues` then `ConstructItems` |
| `AddUninitializedValues(Count)` | 4428-4434 | raw `FScriptArray::Add` — **no construction** |
| `InsertValues(Index, Count)` | 4448-4454 | insert + `ConstructItems` |
| `RemoveValues(Index, Count)` | 4477-4483 | `DestructItems` then `FScriptArray::Remove` |
| `EmptyValues(Slack=0)` | 4459-4471 | `DestructItems(0, OldNum)` then `FScriptArray::Empty(Slack, …)` (frees allocation when Slack==0 ≠ ArrayMax) |
| `Resize(Count)` | 4387-4403 | `AddValues` or `RemoveValues` to reach Count — the right one-call primitive for shadow sync |
| `EmptyAndAddValues` / `EmptyAndAddUninitializedValues` | 4348-4365 | what `CopyValuesInternal` uses |
| `ClearValues` | 4490-4495 | resets elements to default without removing them |
| `SwapValues` | 4502-4505 | raw memswap, no ctors/dtors |

`ConstructItems` memzeroes when the inner has `CPF_ZeroConstructor`, else calls `InnerProperty->InitializeValue(Dest)` per element (`UnrealType.h:4568-4589`). `DestructItems` is a no-op when the inner has `CPF_IsPlainOldData | CPF_NoDestructor`, else calls `InnerProperty->DestroyValue(Dest)` per element (`:4595-4611`). So `AddValues`/`RemoveValues`/`EmptyValues` are fully correct for `FString`/struct inners — construction and destruction are the inner property's own.

## 2. Element addressing and stride

* **`Inner->Offset_Internal` is 0.** `FProperty::Link` = `LinkInternal(Ar)` + `SetupOffset()` (`UnrealType.h:476-480`); `FArrayProperty::LinkInternal` calls `Inner->Link(Ar)` (`Runtime/CoreUObject/Private/UObject/PropertyArray.cpp:77-88`); `SetupOffset` sets `Offset_Internal = Align(0, GetMinAlignment())` = 0 whenever `GetOwner<UObject>()` is null (`Runtime/CoreUObject/Private/UObject/Property.cpp:1269-1288`), and an inner's owner is the `FArrayProperty` — an `FField`, not a `UObject`; `FField::GetOwner<T>` is immediate-owner-only (`Field.h:825-830`; the inner is attached via `FArrayProperty::AddCppProperty`, `PropertyArray.cpp:1252-1258`). Compiled-in inners are also **emitted** with Offset=0, ArrayDim=1: params field order is `…, ArrayDim, Offset, …` (`UObjectGlobals.h:3746-3760`) and a real generated inner reads `…, 1, 0, METADATA_PARAMS…` (`Engine/Intermediate/Build/Linux/UnrealEditor/Inc/Engine/UHT/LevelStreaming.gen.cpp:1254`).
* **Stride is exactly `Inner->GetElementSize()` — never `GetSize()`, never a separately aligned stride.** `GetRawPtr` computes `GetData() + Index * static_cast<size_t>(ElementSize)` (`UnrealType.h:4332`) where `ElementSize` was captured from `Inner->GetElementSize()` (`:4286`). `CopyValuesInternal` uses the same: `size_t Size = Inner->GetElementSize(); … DestData + i * Size` (`PropertyArray.cpp:1278, 1311/1319`). `GetSize()` is `ArrayDim * GetElementSize()` (`UnrealType.h:1208-1211`) and inners always have ArrayDim 1 (previous bullet), so the two coincide for inners — but write `GetElementSize()`.
* **The captured `ElementAlignment` (`Inner->GetMinAlignment()`) is used only for allocation**, passed into `FScriptArray::Add/Insert/Empty/Remove` (`UnrealType.h:4432, 4452, 4469, 4482`), never in address math. There is no inter-element padding beyond what the element size already contains: for struct inners, `FStructProperty::LinkInternal` sets `ElementSize = Align(Struct->PropertiesSize, Struct->GetMinAlignment())` (`Runtime/CoreUObject/Private/UObject/PropertyStruct.cpp:114`) — tail padding is baked into the element size, exactly like `sizeof` on a C++ struct. [inference] For all other inner kinds `ElementSize` is `sizeof(TCppType)` (`TProperty::LinkInternal`, `UnrealType.h:1620-1625`, via `CPPSize = sizeof(TCppType)`, `:1466-1470`), which C++ guarantees is a multiple of the alignment — so stride == element size holds universally.

## 3. Copy semantics

* `CopySingleValue` copies **one element** — memcpy of `GetElementSize()` when `CPF_IsPlainOldData`, else virtual `CopyValuesInternal(Dest, Src, 1)` (`UnrealType.h:881-894`). `CopyCompleteValue` copies **all `ArrayDim` elements** — memcpy of `GetElementSize() * ArrayDim`, else `CopyValuesInternal(Dest, Src, ArrayDim)` (`:915-928`). For an `FArrayProperty` both take the virtual path (an `FScriptArray` is not POD — its computed flags give it only `CPF_ZeroConstructor`: `TIsZeroConstructType<FScriptArray> = true` at `Runtime/Core/Public/Containers/ScriptArray.h:355` region, flags computed at `UnrealType.h:1540-1548`), and both are equivalent because —
* **`FArrayProperty` effectively always has ArrayDim==1.** `FArrayProperty::CopyValuesInternal` opens with `check(Count == 1); // this was never supported, apparently` (`PropertyArray.cpp:1260-1262`), and UHT rejects the declaration outright: "Static arrays of containers are not allowed" (`Types/UhtProperty.cs:2390-2393`). So a C array OF TArrays cannot exist as a UPROPERTY, and if you hand-built one, `CopyCompleteValue` would assert.
* **`FArrayProperty::CopyValuesInternal` is a deep copy** (`PropertyArray.cpp:1260-1328`): dest is emptied and resized to `Src.Num()` (`EmptyAndAddValues` for non-POD inners — elements constructed; `EmptyAndAddUninitializedValues` for POD, `:1266-1274`), then non-POD inners get per-element `Inner->CopyCompleteValue(DestData + i*Size, SrcData + i*Size)` (`:1317-1321`; the `:1287-1314` branch is an AutoRTFM-transaction fast path for exactly-`FObjectProperty` inners, same semantics), POD inners get one `FMemory::Memcpy` (`:1323-1326`). For `FString` elements that lands in `TProperty::CopyValuesInternal` = `FString::operator=` per element (`UnrealType.h:1626-1632`; `FStrProperty` declares no override — grep of `StrProperty.h`/`StrProperty.h.inl` finds none). For struct elements it lands in `FStructProperty::CopyValuesInternal` → `Struct->CopyScriptStruct(Dest, Src, Count)` (`PropertyStruct.cpp:341-344`), which recurses correctly through nested TArray members. So copying the array property IS the correct game→shadow / shadow→slot copy primitive.

## 4. Per-element comparison

* **Yes — the M3a per-kind accessors apply to element pointers directly.** They all take a bare value address: `TPropertyTypeFundamentals::GetPropertyValue(void const* A)` is a cast+deref (`UnrealType.h:1488-1491`); `FNumericProperty::GetSignedIntPropertyValue(void const* Data)` / `GetUnsignedIntPropertyValue` / `GetFloatingPointPropertyValue` (`:1886, 1894, 1902`); `FBoolProperty::GetPropertyValue(void const* A)` applies `ByteOffset`+`FieldMask` to the given address (`:2682-2687`) — and a `TArray<bool>` inner is always a *native* bool (a bitfield cannot exist inside a TArray), so mask = 0xFF and this is a plain byte read. Feed them `Helper.GetRawPtr(i)`; no `_InContainer` variant, no offset arithmetic.
* **`FArrayProperty::Identical`** (`PropertyArray.cpp:89-116`): `B == nullptr` means "is A empty" (`:96-99`); `Num()` mismatch early-out (`:101-105`); then per-element virtual `Inner->Identical(A_i, B_i, PortFlags)` (`:107-113`). Usable and correct; cost = two helper constructions (each one virtual `GetMinAlignment` call, `UnrealType.h:4286`) + N virtual `Identical` calls. For M3b's per-element diff, calling `Inner->Identical` on `GetRawPtr(i)` pairs yourself is the same cost minus one helper construction, and lets you record *which* index changed — `FArrayProperty::Identical` only gives a bool. Caveats from the notes still apply per element: `FTextProperty::Identical` is unreliable in cooked builds; struct inners without `STRUCT_IdenticalNative` do a fresh `TFieldIterator` walk per element.

## 5. Fixed-size C arrays (`UPROPERTY() int32 X[4]`)

* **Addressing:** `ContainerPtrToValuePtr<ValueType>(ContainerPtr, ArrayIndex = 0)` — four overloads (`UObject*`, `void*`, and const variants) at `UnrealType.h:800-819`; the math is `Container + Offset_Internal + GetElementSize() * ArrayIndex` with `checkf(ArrayIndex < ArrayDim)` (`:733-745`). `ArrayIndex` is the static-array index, i.e. exactly "element i from the container ptr".
* **Copy:** `CopySingleValue` = one element at the address you pass (`UnrealType.h:881-894` — note doc: Dest/Src are already element addresses, BASE+OFFSET+INDEX*SIZE, `:873-878`); `CopyCompleteValue` = all `ArrayDim` elements from the base value address (`:915-928`). Likewise `InitializeValue`/`DestroyValue` do "the entire fixed size array" (`:1103-1120`, `:1022-1033`; e.g. memzero of `GetElementSize() * ArrayDim` at `:1114`).
* **What can carry ArrayDim>1:** UHT parses `[dims]` for any member property (`Parsers/UhtPropertyParser.cs:1032-1037, 1056-1064`), then rejects: return types and function parameters (`Types/UhtProperty.cs:2380-2387`), **all containers** — `UhtArrayProperty`/`UhtMapProperty`/`UhtSetProperty`/`UhtOptionalProperty`, everything deriving `UhtContainerBaseProperty` (`UhtProperty.cs:2390-2393`; hierarchy: `Types/Properties/UhtContainerProperty.cs:13`, `UhtSetProperty.cs:20`, `UhtOptionalProperty.cs:21`, `UhtMapProperty.cs:21`) — and **all bools**: "Bool arrays are not allowed" fires for any `UhtBoolProperty` with dimensions, bitfield or native (`UhtProperty.cs:2395-2398`). **`FString X[4]` is legal** — `UhtStrProperty : UhtProperty`, not a container base (`Types/Properties/UhtStrProperty.cs:19`); so are struct fixed arrays (`UhtStructProperty : UhtProperty`, `UhtStructProperty.cs:24`). Fixed arrays also cannot be Blueprint-exposed (`Types/UhtScriptStruct.cs:1147-1149`, `Types/UhtClass.cs:2203-2205`).

## 6. UHT container-nesting rules

* **`TArray<TArray<int>>` — illegal.** `UhtArrayProperty`'s ctor clears `CanBeContainerValue | CanBeContainerKey` on itself (`Types/Properties/UhtArrayProperty.cs:57-58`); the TArray keyword parser then errors "The type '…' can not be used as a value in a TArray" for any value lacking `CanBeContainerValue` (`UhtArrayProperty.cs:257-260`). Default caps *include* `CanBeContainerValue` (`Types/UhtProperty.cs:1252, 1281`), and neither `UhtStructProperty` nor `UhtStrProperty` removes it (no hits in either file).
* **`TArray<FRow>` where FRow itself has a TArray member — legal.** The only struct-specific restriction on array values is direct self-recursion: `TArray<FSelf>` declared inside `FSelf` errors "'Struct' recursion via arrays is unsupported for properties." (`UhtArrayProperty.cs:216-222`). FRow's own TArray member is FRow's own property; nothing inspects it when FRow is used as a container value.
* **Fixed C array of structs containing TArrays — legal.** The static-array check only rejects `UhtContainerBaseProperty` and `UhtBoolProperty` (`UhtProperty.cs:2390-2398`); a struct property is neither. At runtime each fixed-array struct element is a full struct value, and struct init/destroy handles its TArray members (§7).

## 7. Shadow lifecycle: `InitializeStruct` / `DestroyStruct` handle TArray members fully

* `UScriptStruct::InitializeStruct(void* InDest, int32 ArrayDim=1)` (`Runtime/CoreUObject/Private/UObject/Class.cpp:3775-3825`): memzero of `GetStructureSize() * ArrayDim` (`:3780-3783`; `GetStructureSize` = `Align(PropertiesSize, MinAlignment)`, `Class.h:796-799`), then the native ops ctor if present (`:3786-3800`), else per-property `InitializeValue_InContainer` via `PropertyLink` (`:3807-3824`). A zeroed `FScriptArray` is a valid empty array (`TIsZeroConstructType<FScriptArray>` is true, `ScriptArray.h` tail; `FArrayProperty::InitializeValueInternal` is placement-new of `FScriptArray` per ArrayDim, `UnrealType.h:3856-3872`). Either path yields constructed-empty TArray members.
* `UScriptStruct::DestroyStruct(void* Dest, int32 ArrayDim=1)` (`Class.cpp:3933-3981`): early-out for `STRUCT_IsPlainOldData|STRUCT_NoDestructor` (`:3935-3938`); native structs run the real C++ destructor via `TheCppStructOps->Destruct` (`:3944-3953`), which destroys TArray members natively; struct types **without** ops (Blueprint `UUserDefinedStruct`) walk **`DestructorLink`** calling `DestroyValue_InContainer` (`:3960-3980`).
* **`FArrayProperty` participates in `DestructorLink`.** `UStruct::Link` defaults every UScriptStruct property to `LinkDestructor` and removes it only for `CPF_IsPlainOldData | CPF_NoDestructor` (`Class.cpp:1054-1067`, appended at `:1079-1082`); an array property computes only `CPF_ZeroConstructor` (its `FScriptArray` is neither POD nor trivially destructible — flags formula `UnrealType.h:1540-1548`). Its `DestroyValueInternal` destroys all elements (`EmptyValues`) then the container allocation (`DestroyContainer_Unsafe`) (`PropertyArray.cpp:1334-1341`). So: **shadow = `FMemory::Malloc(GetStructureSize(), GetMinAlignment())` + `InitializeStruct` once, `DestroyStruct` + `Free` once — TArray members, including their elements' FStrings, are fully covered on both ends.**

## 8. Pointer stability of `GetRawPtr(i)`

`GetRawPtr` is `GetData() + i*ElementSize` computed **at call time** (`UnrealType.h:4332`) — the helper caches no data pointer, only the `FScriptArray*` itself, so the helper survives reallocation; a **saved** `uint8*` result does not. The allocation moves when:

* **Growth:** `FScriptArray::Add`/`Insert` call `ResizeGrow` only when `ArrayNum+Count > ArrayMax` (`Runtime/Core/Public/Containers/ScriptArray.h:82-97, 60-81`), i.e. appends within existing slack do **not** move data; growth allocates geometric slack via `CalculateSlackGrow` → `DefaultCalculateSlackGrow` (`ScriptArray.h:250-254`; `Runtime/Core/Public/Containers/ContainerAllocationPolicies.h:170-209` — first alloc 4 elements min, then `NewMax + NewMax*factor + 16`, quantized).
* **Shrink on remove:** `FScriptArray::Remove` calls `ResizeShrink` when shrinking is allowed (`ScriptArray.h:191-222`), and the default for the heap allocator **is** allow (`AllowShrinking.h:14, 21-27` — unspecified `ShrinkByDefault` means Yes); `FScriptArrayHelper::RemoveValues` uses that default (`UnrealType.h:4482`). So removals can also realloc.
* **Empty/Resize-to-zero:** `Empty(Slack)` reallocs whenever `Slack != ArrayMax` (`ScriptArray.h:137-148`), including freeing to null at Slack 0. `MoveAssign` swaps whole allocations (`ScriptArray.h:126-136`).
* Additionally `Remove`/`Insert` **memmove the tail** even without realloc (`ScriptArray.h:200-210, 73-78`) — element addresses after the edit point change even when the buffer does not.

Cross-thread rule (stated per the task even though VaCuus never shares an instance): a reader iterating while another thread appends races on `ArrayNum` (plain `int32`, no atomics — `ScriptArray.h:242-243`) *and* can have its data pointer freed under it by `ResizeGrow`'s realloc; there is no engine-side synchronization anywhere in `TScriptArray`. Same-thread rule for M3b: treat any mutation through the helper (or through game code) as invalidating every previously fetched `GetRawPtr` — refetch per element per frame, which is what the call-time arithmetic makes cheap.
