## 1. `Rml::ObserverPtr` — exact semantics

**Mechanism.** `Detail::ObserverPtrBlock` is `{ int num_observers; void* pointed_to_object; }` (`Include/RmlUi/Core/ObserverPtr.h:10-13`). `EnableObserverPtr<T>` holds one lazily-initialized `ObserverPtrBlock* block = nullptr` (`ObserverPtr.h:164`); the block is allocated on the **first** `GetObserverPtr()` call (`ObserverPtr.h:115-119`, `:154-162`), from a process-global pool (`Source/Core/ObserverPtr.cpp:6-10`, `:51-54`, pool of 128-block pages). Cost per element: one pointer member, zero heap until first observation.

**Death.** `~EnableObserverPtr` nulls `block->pointed_to_object` and frees the block only if no observers remain (`ObserverPtr.h:124-131`). A dead handle: `operator bool` → false (`:77`), `get()` → nullptr (`:84`). **`operator->` does NOT null-check** (`:86`) — dereferencing a dead handle is UB; the facade must always test first. Copy/move of the *observed* object never transfers the block (`:133-151`) — an observer tracks the originally-constructed object only.

**Thread caveats.** The header states it outright: "Note: Not thread safe." (`ObserverPtr.h:38`). Stronger: constructing, copying, or **destroying any ObserverPtr** mutates the shared un-mutexed global pool (`reset()` at `ObserverPtr.h:90-98` → `DeallocateObserverPtrBlockIfEmpty`, `Source/Core/ObserverPtr.cpp:12-24`). Consequence for M4: JS wrapper finalizers that drop an `ObserverPtr<Element>` must run on the UI thread — which the spec's "one runtime on the UI thread, GC at a controlled frame point" already guarantees, but no wrapper may leak to a game-thread destructor.

**Pool lifetime.** Initialized in `Rml::Initialise` (`Source/Core/Core.cpp:129`) and shut down in `Rml::Shutdown` (`:185`); if observers still exist at shutdown the pool self-garbage-collects when the last one dies (`Source/Core/ObserverPtr.cpp:33-49` — the comment explicitly blesses user-space `EventListener`s outliving shutdown).

**Does Element derive it?** Yes: `class RMLUICORE_API Element : public ScriptInterface, public EnableObserverPtr<Element>` (`Include/RmlUi/Core/Element.h:47`). So does `EventListener` (`Include/RmlUi/Core/EventListener.h:16`). Bonus: `ScriptInterface` (base of Element, `Include/RmlUi/Core/ScriptInterface.h:13-19`) exists precisely for script bindings — `virtual ScriptObject GetScriptObject()` where `ScriptObject = void*` (`Include/RmlUi/Core/Types.h:14`); a facade Element subclass/instancer could return the JSValue wrapper through it.

## 2. Element creation & ownership outside a document

- `ElementPtr = UniqueReleaserPtr<Element>` (`Include/RmlUi/Core/Types.h:88`) — a unique_ptr whose deleter routes through `Element::Release()` → `instancer->ReleaseElement(this)` (`Source/Core/Element.cpp:2168-2174`). **The caller of `Factory::InstanceElement` owns the returned `ElementPtr`** (`Include/RmlUi/Core/Factory.h:64-70`, `Source/Core/Factory.cpp:313-328`); the `parent` argument is context for the instancer only — no attachment happens. `Document::CreateElement(name)` is literally `Factory::InstanceElement(nullptr, name, name, XMLAttributes())` (`Source/Core/ElementDocument.cpp:427-430`) — it stores **no** document pointer; `owner_document` starts nullptr (`Source/Core/Element.cpp:80`).
- **AppendChild/InsertBefore take `ElementPtr` by value (move)** — ownership transfers into the parent's `children` vector (`Source/Core/Element.cpp:1342-1370` — insert at `:1347`/`:1350`, then `SetParent(this)` at `:1354`; InsertBefore `:1372-1419`). `SetParent` propagates `owner_document` down the subtree (`:2194`, `:2124-2143`) and attaches the parent's data model (`:2201-2219`).
- **RemoveChild returns the `ElementPtr`** — "discard the result to immediately destroy" (`Include/RmlUi/Core/Element.h:519-523`); on removal `SetParent(nullptr)` (`Source/Core/Element.cpp:1492`) → `SetOwnerDocument(nullptr)` (nulls the back-pointer, notifying `Context::OnElementDetach` for hover/active/drag cleanup, `:2129-2134`, `Source/Core/Context.cpp:1116-1146`) and detaches the data model (`:2196-2200`). **So a detached element holds no dangling document/context pointer** and can safely outlive its document — the create-then-append flow and JS-held detached nodes are sound.
- **Document unload:** `Close()` only queues (`Source/Core/ElementDocument.cpp:421-425` → `Context::UnloadDocument`, `Source/Core/Context.cpp:326-345`: unload event + `NotifyDocumentUnload`, tree moved into `unloaded_documents`); actual destruction happens at the next `Context::Update` (`Context.cpp:217`) in `ReleaseUnloadedDocuments` (`:1557-1568`). Elements **inside** the tree at that moment die; the JS side holds only `ObserverPtr`s to attached elements, which then read dead. A JS-held **owning** `ElementPtr` is by definition not in the tree and is untouched. One hard limit: `Release()` needs the instancer alive (`Element.cpp:2170-2171`); default instancers die in `Factory::Shutdown` (`Source/Core/Factory.cpp:279`) — all JS-held `ElementPtr`s must be dropped before `Rml::Shutdown` (the spec's shutdown order — JS runtime before contexts — already satisfies this).
- Tag-case trap for `createElement`: registered instancer names are lowercased (`Factory.cpp:297`) but lookup is not (`:302`), and the Element ctor asserts lowercase only in debug (`Element.cpp:76`) — with the plugin's asserts compiled out, `createElement("DIV")` silently instances a generic element whose tag never matches RCSS (the XML parser lowercases parsed tags — data-binding note §8.8). The facade should lowercase tag names itself. *Experiment E1 below.*

## 3. Events

- **Listener interface:** `virtual void ProcessEvent(Event&) = 0`, `virtual void OnAttach(Element*)`, `virtual void OnDetach(Element*)` (`Include/RmlUi/Core/EventListener.h:21-27`).
- **AddEventListener overloads:** by `const String&` and by `EventId`, both with trailing `bool in_capture_phase = false` (`Include/RmlUi/Core/Element.h:471`, `:475`); removal mirrors (`:480`, `:482`). The string overload resolves via `EventSpecificationInterface::GetIdOrInsert` — **it mutates the process-global type registry** if the name is new (`Source/Core/Element.cpp:1236-1240`; `Source/Core/EventSpecification.cpp:135-144`). The documented lifetime contract: the listener must stay alive until after `OnDetach` (`Element.h:469-470`).
- **Detach guarantees / order — the JS ref-release path.** Attach fires `OnAttach` once per (id, listener, phase) entry, duplicates ignored (`Source/Core/EventDispatcher.cpp:40-52`); `RemoveEventListener` fires `OnDetach` (`:54-62`). On **direct element destruction** (`Source/Core/Element.cpp:95-116`): ① `PluginRegistry::NotifyElementDestroy(this)` (`:99`), ② `meta` destroyed (`:112`) — `ElementMeta` embeds the `EventDispatcher` (`Source/Core/ElementMeta.h:18-27`) whose destructor calls `OnDetach` for every remaining entry (`EventDispatcher.cpp:33-38`), ③ children destroyed (`:114`), each repeating ①-③. So per element: **OnElementDestroy → OnDetach → children**. On **document unload** the order inverts: `ReleaseUnloadedDocuments` calls `DetachAllEvents()` on the whole tree first (`Source/Core/Context.cpp:1565-1566`; recursive, clears the listener lists — `EventDispatcher.cpp:64-73`) and only then destroys elements — **all OnDetach before any OnElementDestroy**, and the destructor's OnDetach loop then iterates an empty list (no double-fire). The facade must release JS refs from `OnDetach` and tolerate both orders. *Experiment E2.*
- **Event surface:** `GetParameter<T>(key, default)` / `GetParameters()` (`Include/RmlUi/Core/Event.h:77-84`), `GetTargetElement()` / `GetCurrentElement()` (`:45-47`), `GetPhase()` (`:38`, `EventPhase {None, Capture, Target, Bubble}` `:15`), `StopPropagation()` / `StopImmediatePropagation()` (`:55-57`) — stopping works only if `interruptible` (`:59-60`). **There is no `preventDefault` separate from propagation**: default actions run via `ProcessDefaultAction` after listeners and are skipped once `!event->IsPropagating()` (`Source/Core/EventDispatcher.cpp:173-185`) — `stopPropagation` is the closest analog; a JS `preventDefault` can only map onto that.
- **Dispatch:** three `DispatchEvent` overloads including one overriding interruptible/bubbles per call (`Element.h:487-491`; impl `Element.cpp:1258-1276`). Dispatch collects the capture→target→bubble chain up front, holding **ObserverPtrs to both elements and listeners** so mid-dispatch destruction is safe (`EventDispatcher.cpp:81-99`, `:163-167`).
- **Custom EventId registration:** `Rml::RegisterEventType(type, interruptible, bubbles, default_action_phase)` (`Include/RmlUi/Core/Core.h:149`, `Source/Core/Core.cpp:369-372` → `InsertOrReplaceCustom`, `EventSpecification.cpp:146-163`). String-dispatch of an unknown type auto-registers with defaults interruptible=true, bubbles=true (`EventSpecification.cpp:125-133`). Custom ids start at `EventId::FirstCustomId`, cap `MaxNumIds = 0xffff` (`Include/RmlUi/Core/ID.h:242-249`).

## 4. querySelector family

All three exist: `QuerySelector` / `QuerySelectorAll` / `Matches` (`Include/RmlUi/Core/Element.h:544-553`) plus `Closest` (`:415`). They parse the selector with the **same machinery as RCSS** (`StyleSheetParser::ConstructNodes`, `Source/Core/Element.cpp:1587-1613`, `:1615-1631`, `:1066-1090`; `Source/Core/StyleSheetParser.cpp:947-967` — comma-splitting respects parentheses). Supported per `Source/Core/StyleSheetSelector.h`: all four combinators (descendant, `>`, `+`, `~`, `:26-31`), attribute selectors `[a]`, `=`, `~=`, `|=`, `^=`, `$=`, `*=` (`:38-46`), and structural pseudo-classes `:nth-child`/`:nth-last-child`/`:nth-of-type`/`:nth-last-of-type`/`:first/last/only-child`/`:*-of-type`/`:empty`/`:not()`/`:scope` (`:69-84`). Limitations: matching starts at **children** — `QuerySelector` never matches the element itself (`Element.cpp:1544-1546`) and `Closest` starts at the **parent**, excluding self, unlike DOM `closest()` (`Element.cpp:1077-1090`); `#text` nodes are skipped (`:1547`); an invalid selector logs `LT_WARNING` and returns null/empty (`:1592-1596`).

## 5. classList / style / attributes

- **classList:** `SetClass(name, activate)` (`Element.h:65`, impl `Element.cpp:258-262`), `IsClassSet` (`:264-266`), `SetClassNames` / `GetClassNames` (`:269-276`). Trap: `SetClassNames` routes through `SetAttribute("class", …)` (`:271`) but `SetClass` mutates `meta->style` **directly and does not update the `class` attribute** — so `GetAttribute("class")` goes stale; the facade's classList must read via `GetClassNames()`, never the attribute.
- **style proxy:** `SetProperty(String, String)` parses full declarations including shorthands, custom `--props`, and `var()` shorthands (`Element.cpp:591-614`); `RemoveProperty(String)` handles longhand, `--custom`, and expands shorthands (`:621-646`); `GetProperty(String)` returns a `const Property*` **invalidated by any following RmlUi call** — copy immediately (`Element.h:187-193`), `Property::ToString()` used for serialization exists (used at `Element.cpp:2101`). This is exactly the shape a JS string-based `element.style` proxy needs: get → `GetProperty(name)?->ToString()` copied at once; set → `SetProperty(name, value)` (returns parse success `Element.h:176-177`); remove → `RemoveProperty(name)`.
- **attributes:** `SetAttribute<T>` writes the map then synchronously calls `OnAttributeChange` with the one changed entry (`Include/RmlUi/Core/Element.inl:15-23`); `RemoveAttribute` likewise notifies with an empty variant (`Element.cpp:866-876`); getters at `Element.h:288-314`. `OnAttributeChange` is a **protected virtual on Element** (`Element.h:616-618`) — not a plugin hook; observing attribute changes from outside requires a facade Element subclass, but the built-in handling already covers the facade's needs: `id`, `class`, `style` (parsed into properties), `on*`/`on*capture` attributes instancing event listeners via the global `EventListenerInstancer` (`Element.cpp:1703-1773`; listener instancer registry `Factory.cpp:145`, `:549`, `:552-556` — M4's hook for `onclick="…"` JS snippets), and any change dirties self+siblings definitions for attribute selectors (`:1802-1804`).

## 6. innerRML

`GetInnerRML` serializes children via `GetRML` recursion (`Element.cpp:1152-1165`). `SetInnerRML` (`:1167-1177`): removes every **DOM** child via `RemoveChild` **discarding the returned ElementPtr** — each old child is therefore destroyed synchronously inside the call (destructor path of §3: OnElementDestroy → listener OnDetach, recursively for grandchildren), then parses the new string with `Factory::InstanceElementText` (`:1175-1176`). Non-DOM children (scrollbars) survive (`:1172`). Consequences for JS: element identity is never preserved (all JS handles to replaced children go dead, their listeners get `OnDetach` before `SetInnerRML` returns), and — per data-binding note §8.7 (`/w/Unreal/VaCuus/docs/research/m3-api-notes/rmlui-data-binding.md:1142-1146`) — new children on a model-attached element **do** get data views via `AppendChild → SetParent → SetDataModel` (`Element.cpp:1342-1370`, `:2206`).

## 7. Document/script hooks

- **`<script>` exists — but only in `<head>`.** There is no dedicated script node handler (`Source/Core/` has only Body/Default/Head/Template handlers, registered at `Source/Core/Factory.cpp:260-268`). `XMLNodeHandlerHead` collects `<script src>` (external, `Source/Core/XMLNodeHandlerHead.cpp:84-91`) and inline script text (`:126-129`) into `DocumentHeader::scripts` (one vector, document order; `Source/Core/DocumentHeader.h:35`). When `</head>` closes, `ProcessHeader` runs (`XMLNodeHandlerHead.cpp:98-110`) and calls the **virtual** `ElementDocument::LoadInlineScript(content, source_path, source_line)` / `LoadExternalScript(source_path)` (`Source/Core/ElementDocument.cpp:217-228`; declarations `Include/RmlUi/Core/ElementDocument.h:106-113`; base impls empty, `ElementDocument.cpp:461-463`). **Timing trap:** this happens mid-parse, before `<body>` exists and before the document joins the context — M4 should capture scripts at `LoadInlineScript` time (requires a facade ElementDocument subclass via a document instancer) or defer execution to `OnDocumentLoad`/the `load` event; a `<script>` in `<body>` never reaches these hooks (it would be instanced as a plain unknown element by the default handler — handler registry `Source/Core/XMLParser.cpp:69-93`, `:111-119`).
- **Plugin interface** (`Include/RmlUi/Core/Plugin.h:20-61`): opt-in classes `EVT_BASIC/DOCUMENT/ELEMENT/DATA_MODEL` via `GetEventClasses` (`:20-29`); hooks `OnDocumentOpen` (before file open, `Source/Core/Context.cpp:285`), `OnDocumentLoad` (after instancing+append, **before** the document's `load` event, `Context.cpp:299-300`), `OnDocumentUnload` (after the `unload` event, `Context.cpp:340-341`), `OnElementCreate` (from `Factory::InstanceElement` only, `Factory.cpp:322`), `OnElementDestroy` (from `~Element`, `Element.cpp:99`), plus context and data-model pairs (`Context.cpp:107`, `:113-114`; `Context.cpp` data model create per M3 note §1).
- **Live reload fires the full set.** VaCuus live reload is a whole-document reload: `LoadDocumentFromFile` → `Context::LoadDocument` for the **new** document (OnDocumentOpen/OnDocumentLoad + head scripts), then `AdoptDocument` closes the **old** one (`Source/VaCuusRender/Private/VaCuusRmlDocumentHost.cpp:148-162`, `:179-217` — note new-loads-before-old-closes: two documents are alive for an instant), `CloseDocument` queues the unload (`:234-248` — its comment documents the deferred free), old-tree `OnElementDestroy`s arrive at the next `Context::Update` (`Context.cpp:217`, `:1557-1568`).
- **Veto/observe destruction:** **observe only, no veto** — `NotifyElementDestroy` is called from inside the destructor (`Element.cpp:99`); the object is already dying. Timing vs `OnDetach`: OnElementDestroy strictly precedes the same element's listener OnDetach on the direct path, and strictly follows the tree-wide OnDetach sweep on the unload path (§3). Two more cleanup facts for the facade map: **[inference]** during `OnElementDestroy` the element's `ObserverPtr`s still read alive, because `~EnableObserverPtr` (a base of Element, `Element.h:47`) runs after the `~Element` body that fires the hook (`ObserverPtr.h:124-131`) — so map erasure must key on the raw pointer, not on `observer.get() == nullptr`; and **[inference]** derived-class destructors have already run when the hook fires, so custom-RTTI casts see only `Element`. Also: `Element::Clone` with an instancer bypasses `Factory::InstanceElement` (`Element.cpp:214-225`) — **no `OnElementCreate` for clones**; a facade map populated only from that hook will miss them (wrap lazily on first JS access instead).

## 8. requestAnimationFrame timing source

RmlUi has exactly one clock: `GetSystemInterface()->GetElapsedTime()`, wrapped by `Clock::GetElapsedTime` (`Source/Core/Clock.cpp:7-14`). `Context::Update` itself never reads time (`Source/Core/Context.cpp:181-220`); time enters during `root->Update` when each element's animations advance — `AdvanceAnimations` samples `Clock::GetElapsedTime()` (`Source/Core/Element.cpp:2838-2849`; animation/transition start times `:2623`, `:2669`), and input paths sample the system interface directly (`Context.cpp:658`, `:947`, `:998`). VaCuus implements it as `FPlatformTime::Seconds() - StartTime` (`Source/VaCuus/Private/VaCuusSystemInterface.cpp:62-65`). **Therefore the rAF timestamp must be `GetSystemInterface()->GetElapsedTime()` sampled once at the top of the JS pump** — sampled before `Context::Update`, it is ≤ the animation clock inside the same frame by only the pump's own duration; there is no per-frame frozen time in RmlUi to diverge from.

## 9. Threading / process-global collision on the facade path

Everything the facade touches is UI-thread-only, consistent with the existing invariant. The process-global singletons on this path (the `Family<T>` analogs from the M3 note, `Include/RmlUi/Core/Traits.h:51-61`):

| Global | Where | Mutated by facade ops? |
|---|---|---|
| ObserverPtr block pool | `Source/Core/ObserverPtr.cpp:6-10` | every GetObserverPtr / ObserverPtr copy/destroy (§1) |
| Event type registry | `Source/Core/EventSpecification.cpp:52` | `AddEventListener(String)` / `DispatchEvent(String)` with a new name inserts (`:105-117`) |
| Factory instancer maps + event-listener instancer | `Source/Core/Factory.cpp:141`, `:145` | createElement lookups (read), `on*` attributes (read) |
| ElementMeta pool | `Source/Core/ElementMeta.h:29-35`, alloc `Element.cpp:91`, free `:112` | every element create/destroy |
| XML node-handler map | `Source/Core/XMLParser.cpp:69-93` | innerRML/document parse (read) |

None are mutex-protected; none are per-context. Two **views** never collide because both live on the single process-wide UI thread (architecture: one thread owns every `Rml::Context`). Two **worlds/subsystems** likewise share that thread, so their JSRuntimes are serialized — but note the sharing is *visible*: a custom event type registered by one subsystem's JS occupies a global `EventId` slot seen by all (`EventSpecification.cpp:114-116`), and ids never unregister until `Rml::Shutdown` (`:79-82`) — benign (65 535-slot cap, `ID.h:248`) but worth a comment in VaCuusJs. The hard rule the facade adds: **JS GC and wrapper finalization must run on the UI thread**, because releasing an `ObserverPtr` or `ElementPtr` off-thread races the global pools (§1) — the spec's controlled-frame-point GC already satisfies this; assert it (`FVaCuusUIThread::IsInUIThread()` as the host code already does, e.g. `Source/VaCuusRender/Private/VaCuusRmlDocumentHost.cpp:150`).

## Named experiments (restore-the-bug candidates for M4)

- **E1 — uppercase tag silent fallback:** with asserts compiled out, `document.createElement("DIV")` should produce a generic element whose tag never matches an RCSS `div` rule (`Factory.cpp:297` vs `:302`; `Element.cpp:76`). Test: create `"DIV"`, append, assert a `div { … }` stylesheet rule does *not* apply; then lowercase in the facade and watch it apply.
- **E2 — OnDetach/OnElementDestroy order differs by death path:** attach a logging listener, then (a) `RemoveChild` + drop the `ElementPtr` → expect destroy-then-detach (`Element.cpp:99` → `:112`); (b) `Document->Close()` + one `Context::Update` → expect detach-then-destroy (`Context.cpp:1565-1567`). The facade's ref-release must pass both; break it by releasing only in one hook and watch the other path leak (QuickJS heap-count observable per the spec's memory cap).
- **E3 — listener OnDetach inside SetInnerRML:** listener on a child, parent `SetInnerRML("")` — assert OnDetach fired synchronously before the call returned (`Element.cpp:1171-1173` discards the RemoveChild result). This is the observable for the JS-ref invariant of §6.
