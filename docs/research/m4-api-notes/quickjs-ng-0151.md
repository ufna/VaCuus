## 2. Lifecycle

- `JS_NewRuntime(void)` — `quickjs.h:490`; impl is just `JS_NewRuntime2(&def_malloc_funcs, NULL)` (`quickjs.c:2080-2083`, defaults at `quickjs.c:2072-2078`).
- `JS_NewRuntime2(const JSMallocFunctions *mf, void *opaque)` — `quickjs.h:504`. **ng `JSMallocFunctions` shape** (`quickjs.h:451-457`): five hooks — `js_calloc(opaque,count,size)`, `js_malloc(opaque,size)`, `js_free(opaque,ptr)`, `js_realloc(opaque,ptr,size)`, `js_malloc_usable_size(ptr)`. Yes, a state pointer: the `opaque` from `JS_NewRuntime2` is passed as first arg to the first four (stored in `JSMallocState.opaque`, `quickjs.c:252-257`, wired at `quickjs.c:1964-1965`, used e.g. `quickjs.c:1649`). `js_malloc_usable_size` may be NULL → dummy returning 0 (`quickjs.c:1972-1975`). Accounting adds `usable_size + MALLOC_OVERHEAD` per block (`quickjs.c:1654`).
- `JS_NewContext` — `quickjs.h:516`; = `JS_NewContextRaw` + intrinsics Base, Date, Eval, RegExp, JSON, Proxy, MapSet, TypedArrays, Promise, WeakRef, AToB, Performance (`quickjs.c:2533-2557`). Note `JS_AddIntrinsicBigInt` (`quickjs.h:539`) is **not** in that list — see experiment E3.
- **Ordering/leak behavior:** `JS_FreeContext` is refcounted (`quickjs.c:2676-2683`). Free all contexts (and all held `JSValue`s) before `JS_FreeRuntime`. `JS_FreeRuntime` (`quickjs.c:2288`) frees still-queued jobs' args itself (`quickjs.c:2297-2303`), runs a final GC (`quickjs.c:2305`), then **`assert(list_empty(&rt->gc_obj_list))` (`quickjs.c:2348`)** — a leaked context/object aborts a debug (assert-enabled) build; in NDEBUG it proceeds. Leak *dumps* exist only when compiled with `ENABLE_DUMPS` and `JS_DUMP_LEAKS` flag set (`quickjs.c:2307-2346`; flags `quickjs.h:475-481`); deliberate abort only via `JS_ABORT_ON_LEAKS` (`quickjs.h:481`, `quickjs.c:2483,2490-2491`). Runtime finalizers registered with `JS_AddRuntimeFinalizer` (`quickjs.h:508-509`) run LIFO at the very end (`quickjs.h:483-486`, `quickjs.c:2462-2467`). This matches the M4 shutdown order: kill documents (freeing DOM-facade values) while ctx alive → `JS_FreeContext` → `JS_FreeRuntime`.

## 3. Limits

- `JS_SetMemoryLimit(rt, limit)` — `quickjs.h:493-494`, "use 0 to disable"; sets `malloc_state.malloc_limit` (`quickjs.c:2085-2088`). At the limit allocators return NULL (`quickjs.c:1645-1647`; the `limit - 1` trick makes 0 mean SIZE_MAX, comment `quickjs.c:1645`); ctx-level `js_malloc` then throws (`quickjs.c:1734-1743`) via `JS_ThrowOutOfMemory` → **InternalError "out of memory"** (`quickjs.c:8130-8135`). Exception, never abort. (One abort exists: allocator-accounting *underflow*, a corruption guard, `quickjs.c:1667-1670`.)
- `JS_SetMaxStackSize(rt, size)` — `quickjs.h:499-500`, 0 disables; impl `quickjs.c:2772-2776`. Default `JS_DEFAULT_STACK_SIZE` = 1 MiB (`quickjs.h:423-425`, applied `quickjs.c:2014`). At the limit `js_check_stack_overflow` (`quickjs.c:1952-1957`) makes the engine throw **RangeError "Maximum call stack size exceeded"** (`quickjs.c:8138-8141`). Exception, not abort — but it's a *native* stack check: the budget must fit inside the UI thread's real stack.
- `JS_SetGCThreshold(rt, t)` — **exists in ng**: `quickjs.h:498`, impl `quickjs.c:2111-2114` with the comment **"use -1 to disable automatic GC"** (`quickjs.c:2110`). Default threshold 256 KiB (`quickjs.c:1980`). `JS_GetGCThreshold` (`quickjs.h:497`, `quickjs.c:2106-2108`).
- `JS_UpdateStackTop(rt)` — `quickjs.h:501-503`: "should be called when changing thread to update the stack top value used to check stack overflow". Impl records the current stack pointer and recomputes `stack_limit = stack_top - stack_size` (`quickjs.c:2778-2782`, `2764-2768`). Captured once at `JS_NewRuntime2` (`quickjs.c:2019`) — see §11.

## 4. GC

- `JS_RunGC` (`quickjs.h:513`) is a synchronous three-phase cycle collector — `gc_decref` / `gc_scan` / `gc_free_cycles` (`quickjs.c:7078-7089`) — running entirely on the calling thread. There is no incremental or concurrent mode; "stop-the-world" is vacuous because a runtime is single-threaded by contract (`docs/docs/developer-guide/intro.md:14`). Pause is proportional to the live GC-object graph.
- **Implicit trigger:** `js_trigger_gc` (`quickjs.c:1583-1602`) runs GC when `malloc_size + size > malloc_gc_threshold`, then re-arms the threshold to 1.5× live size (`quickjs.c:1599-1600`). Its **only call site** is object allocation, `JS_NewObjectFromShape` (`quickjs.c:5748`; grep confirms no other) — plain malloc/strings never trigger it.
- **The frame-controlled design holds:** `JS_SetGCThreshold(rt, (size_t)-1)` disables the implicit path (`quickjs.c:2110`), leaving `JS_RunGC` at the frame point as the only collector. Caveat that must go in the M4 doc: allocation failure at the 16MB memory cap does **not** retry after a GC — `js_malloc_rt` returns NULL immediately (`quickjs.c:1645-1647`), so the OOM InternalError fires even if a collection would have freed space. The frame-point GC must run frequently enough, or the pump should `JS_RunGC` once on OOM and re-signal.

## 10. Strings

- `JS_NewStringLen(ctx, buf, len)` takes **UTF-8** ("create a string from a UTF-8 buffer", `quickjs.c:4370-4371`). Invalid UTF-8 does **not** throw — the error path is deliberately commented out and bytes are decoded permissively (`quickjs.c:4400-4407`); storage is 8-bit or UTF-16 chosen by scan (`quickjs.c:4380-4408`).
- `JS_ToCStringLen2(ctx, &len, val, cesu8)` (`quickjs.h:879`; wrappers `JS_ToCString(Len)` `quickjs.h:880-887`) returns UTF-8 in which **unmatched surrogates are kept** rather than replaced (comments "Keep unmatched surrogate code points", `quickjs.c:4561-4575`) — i.e., output can be WTF-8; well-formed JS strings yield clean UTF-8. `cesu8=true` forces CESU-8 pairs. FString conversion must tolerate this (or pre-sanitize; see E4).
- Lifetime: the returned pointer lives until `JS_FreeCString(ctx, ptr)` (`quickjs.h:899`); the ASCII fast path returns an interior pointer of the source string (`quickjs.c:4528-4532`), so the free call is mandatory, pointer must not outlive the value. UTF-16 variants: `JS_NewStringUTF16` (no validity check — caller's job, `quickjs.h:872-875`), `JS_ToCStringLenUTF16` (`quickjs.h:888-893`).

## 11. Threading

- The whole official statement: **"Inside a given runtime, no multi-threading is supported"** (`docs/docs/developer-guide/intro.md:14`). Multiple runtimes may coexist but cannot exchange objects (same file, lines 12-14).
- **There is no thread-identity enforcement in core**: grep for `pthread_self`/`GetCurrentThreadId`/`thrd_current`/`thread_id` over `quickjs.c` finds nothing (verified, exit 1). Nothing checks *which* thread calls; the contract is exclusion, not identity.
- The only thread-*sensitive* state is the stack anchor: `JS_NewRuntime2` captures `stack_top` on the creating thread (`quickjs.c:2019`), and `js_check_stack_overflow` compares the current stack pointer against `stack_top - stack_size` (`quickjs.c:1952-1957`, `2767`). **"Created on thread A, used only on thread B" is legal provided `JS_UpdateStackTop(rt)` runs on B before any JS executes** — that is exactly what the API comment prescribes ("should be called when changing thread", `quickjs.h:501-503`). Without it, B's stack pointer is compared against A's anchor: spurious or missed "Maximum call stack size exceeded". For the commandlet inline mode (game thread runs the pump): sequenced, exclusive access + `JS_UpdateStackTop` at each thread handoff is sufficient by the documented contract; see E2.

## Named experiments (unsettleable from source reading alone)

- **E1 — TLA detection**: eval `vfs://` module with `await new Promise(()=>{})` at top level; assert `JS_PromiseState(ret) == JS_PROMISE_PENDING` after draining `JS_ExecutePendingJob`, and that a TLA-free module reaches `JS_PROMISE_FULFILLED` within the same pump. Grounds the "refuse pending module promises" policy on observed behavior, not on the internal `has_tla` (`quickjs.c:37392`).
- **E2 — cross-thread create/use**: create runtime on game thread, run a deep-recursion script on the UI thread with and without `JS_UpdateStackTop`; expect correct RangeError with it and a spurious/absent overflow without. Proves the commandlet inline mode contract.
- **E3 — BigInt in default context**: eval `typeof 1n` in a plain `JS_NewContext` — `JS_AddIntrinsicBigInt` (`quickjs.h:539`) is absent from `JS_NewContext`'s intrinsic list (`quickjs.c:2540-2551`); determine whether BigInt is baked into base objects or must be added explicitly before deciding the Tier-1 context recipe.
- **E4 — WTF-8 round-trip**: push a lone surrogate (`"\uD800"`) through `JS_ToCString` → `FUTF8ToTCHAR`; verify UE's converter doesn't mangle or assert, else add a sanitize pass at the facade boundary (`quickjs.c:4561-4575` is why).
- **E5 — GC-disabled OOM**: with `JS_SetGCThreshold(rt,-1)` and `JS_SetMemoryLimit(16MB)`, allocate garbage past 16MB without frame-point GC; confirm InternalError "out of memory" with no collection attempt (`quickjs.c:1645-1647`), justifying an on-OOM `JS_RunGC`-and-retry in the pump.
