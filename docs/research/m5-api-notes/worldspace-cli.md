## 1. What UVaCuusWorldComponent minimally is

**Engine precedent, verified.** `UWidgetComponent : public UMeshComponent` (`WidgetComponent.h:95`). Its world-space render path is: a custom `FWidget3DSceneProxy : FPrimitiveSceneProxy` that builds a 4-vertex quad per frame with `FDynamicMeshBuilder` — vertices spanning `DrawSize` pixels as world units, UV 0..1, drawn with the component's `UMaterialInstanceDynamic` render proxy (`WidgetComponent.cpp:310-411`, plane branch `:381-411`). Collision is a hand-built `UBodySetup` box, 0.01 uu thick, `CTF_UseSimpleAsComplex` (`:2006-2033`), collision profile `"UI"` (`:653`), plus `CalcBounds`/`GetCollisionShape` overrides (`:907-948`).

**Material machinery, verified.** Six shipped engine materials — `/Engine/EngineMaterials/Widget3DPassThrough_{Translucent,Opaque,Masked}[_OneSided]` (`WidgetComponent.cpp:656-671`), selected by `BlendMode`/`bIsTwoSided` in `GetMaterial(0)` (`:2330-2338`). A `UMaterialInstanceDynamic` is created over that base in `UpdateMaterialInstance()` (`:785-808`) and fed three parameters: `SlateUI` (the RT texture), `TintColorAndOpacity`, `OpacityFromTexture` (`UpdateMaterialInstanceParameters`, `:2349-2357`; also re-pushed on RT recreation at `:1973` and instance-data reapply `:1612`). The documented parameter contract is in the class comment (`WidgetComponent.h:88-92`).

**What we clone vs replace:**

| Piece | Verdict |
|---|---|
| `UMeshComponent` base + quad proxy (`:310-411`) + `UBodySetup` box (`:2006-2033`) | **Clone.** Pixel-sized `DrawSize` semantics, no content-mesh dependency. [inference] A `UStaticMeshComponent` + `/Engine/BasicShapes/Plane` would also work but sizes via scale hacks and gives up the `GetLocalHitLocation` convention below verbatim. |

| `WidgetClass`/`InitWidget`/tick-driven `DrawWidgetToRenderTarget` | **Replace with the existing view pipeline**: component creates its view exactly as the UMG widget does — `Subsystem->CreateView(MakeUnique<FVaCuusRmlDocumentHost>(Sink), DrawSize)` (`VaCuusUMGWidget.cpp:75-76`, subsystem side `VaCuusSubsystem.cpp:139-181`). Unlike the widget's deliberate zero initial size (`VaCuusUMGWidget.cpp:69-76` — UMG hasn't laid it out yet), a world panel's pixel size **is** `DrawSize`, known at creation, so pass it and skip the first-tick resize dance. ## 2. The RT bridge (the crux) — settled

**Our RT is not a UTexture and never was.** `FVaCuusReplayRenderer::OutputRT` is a raw `FTextureRHIRef` created on the render thread by `RHICmdList.CreateTexture` — `PF_B8G8R8A8`, `RenderTargetable|ShaderResource`, initial/invariant state `SRVMask` (`VaCuusReplayRenderer.cpp:151-173`, header `VaCuusReplayRenderer.h:52-62,113`). It is **recreated (new RHI pointer) on any ViewSize change** (`:159-172`). The screen path never needs a UTexture: the Slate element registers it with RDG per frame (`RegisterExternalTexture`, `VaCuusSlateElement.cpp:106`).

**Materials bind UTextures through `FRHITextureReference`, verified**: the uniform-expression path requires `Value->GetResource()` non-null and binds `Value->TextureReference.TextureReferenceRHI` (`MaterialUniformExpressions.cpp:1708-1729`). So the world path must produce a `UTexture` whose reference resolves to our pixels.

**Second structural fact: nothing drives a replay for a world view.** `Draw_RenderThread` only runs because `SVaCuusWidget::OnPaint` submits the element via `FSlateDrawElement::MakeCustom` (`SVaCuusWidget.cpp:286`); the host publishes buffers to a `TSharedPtr<FVaCuusSlateElement>` hard-typed member (`VaCuusRmlDocumentHost.h:94`, publish at `VaCuusRmlDocumentHost.cpp:491-495`, release at `:131-134`). **Required refactor:** extract the three calls the host actually makes (`SetPendingBuffer_RenderThread`, `ReleaseResources_RenderThread`, ~~SetDestRect~~) into an `IVaCuusFrameSink` interface; `FVaCuusSlateElement` implements it unchanged; the world component provides `FVaCuusWorldSink`.

**Recommended bridge (Option A — copy-on-publish):**
1. Component owns a `UTextureRenderTarget2D`, created/resized on the game thread exactly as `UWidgetComponent::UpdateRenderTarget` does (`WidgetComponent.cpp:1940-2004`: `NewObject` + `InitCustomFormat` + `SetTextureParameterValue` on create, `InitCustomFormat`+`UpdateResourceImmediate` on resize) — format `PF_B8G8R8A8`, **not** sRGB (matches the replay RT, `VaCuusReplayRenderer.cpp:166-167`).
2. `FVaCuusWorldSink::SetPendingBuffer_RenderThread` replays **immediately in the enqueued render command** (arrival-driven — exactly spec §4's replay model: "Arrival of a new command buffer triggers re-replay into the RT; otherwise the RT is reused as-is", spec:129-131). The replayer is raw-RHI and legal outside RDG (`Replay` does its own transitions/`BeginRenderPass`, `VaCuusReplayRenderer.cpp:231-358`). Keep the element's drain discipline: only the newest queued buffer draws, older ones go through `ConsumeResources` (`VaCuusSlateElement.cpp:79-83`; mid-pass-recreate tripwire `VaCuusReplayRenderer.cpp:59-63`).
3. After `Replay`, `CopyTexture` OutputRT → the RT resource's RHI texture (transition `SRVMask→CopySrc→SRVMask` around it; OutputRT is in `SRVMask` outside Replay by invariant, `:171,358`). Cost: one GPU copy **per published frame** — and the idle gate makes published frames rare (2 of 13,074 on the static HUD, spec:339), so an idle world panel costs zero copies and the `UTextureRenderTarget2D` retains the pixels. This also sidesteps the RT-recreate-on-resize problem: the material binds the UTexture's stable reference, never our transient RHI pointer.

**Rejected alternatives, with reasons from source:**
- **Zero-copy repoint** (custom `UTexture` + `UpdateTextureReference(TextureRef, OutputRT)`, the media-texture mechanism; non-deprecated form `RHICommandList.h:905`): viable — M2's own research reserved it for exactly this ("Reserve FRHITextureReference for a future UTexture/material-facing surface", `docs/research/m2-api-notes/debt.md:90`) — but each update costs an `RHIThreadFence(true)` (debt.md:78 citing DynamicRHI.cpp:590), Epic marks the whole mechanism for eventual removal (debt.md:396), and it needs a custom UTexture subclass + resource. More code for a copy that idle-gating already made negligible. Keep as the v1.x optimization if profiling ever shows the copy.
- **Replay directly into the UTextureRenderTarget2D's texture**: requires teaching `FVaCuusReplayRenderer` an external RT and breaks its own recreate/ensure coupling (`EnsureOutputRT` owns sizing, `:151-173`); invasive for the same saving.

## 3. Input: raycast → UV → pixels → the existing enqueue

**The engine's hit→widget-space math, verified** — `UWidgetComponent::GetLocalHitLocation` (`WidgetComponent.cpp:2036-2054`): `ComponentTransform.InverseTransformPosition(WorldHit)` → 2D as `(-Local.Y, -Local.Z)` → `+ DrawSize * Pivot`. Because the quad's world units are pixels, the result **is already RT pixel space**. Our analog is these 12 lines verbatim (plane only); front-face gating is the dot-product test at `WidgetComponent.cpp:186-189`.

**Where the ray comes from.** Precedents: `FWidget3DHitTester` uses `PlayerController->GetHitResultAtScreenPosition(ScreenPos, ECC_Visibility, ...)` cached per (frame, position) (`WidgetComponent.cpp:259-279`); `UWidgetInteractionComponent::PerformTrace` offers World (component X-axis ray, `WidgetInteractionComponent.cpp:159-176`), Mouse/CenterScreen (`DeprojectScreenToWorld` + `LineTraceMultiByChannel`, `:177-228`), and Custom (caller-supplied hit, `:229-237`).

**What we do NOT reuse:** UMG's whole delivery machinery — `FWidgetPath`/`GetHitWidgetPath` via the virtual window's hit-test grid (`WidgetComponent.cpp:2202-2215`), the `SVirtualWindow`, `ICustomHitTestPath` redirection (`:153-257`), and `UWidgetInteractionComponent`'s virtual Slate user (`WidgetInteractionComponent.cpp:72-91`). Our input is enqueue+snapshot: the game thread already answers Slate from published rects and queues events (`SVaCuusWidget.cpp:404-415`), and the view's `SendInput` → `UIThread->EnqueueInput` path is host-agnostic (`VaCuusView.cpp:573-601`).

**Minimal shape (matches spec §8:284-285 and the M2 note's skeleton, slate-input.md:522-545):**
- One process-wide `FVaCuusWorldInputProcessor : IInputProcessor`, registered `PreGame` on first component registration, unregistered (with the `FSlateApplication::IsInitialized()` guard) when the last leaves — the refcount idiom of `RegisterHitTesterWithViewport`/`Unregister` (`WidgetComponent.cpp:1097-1138`). [inference] Registration bookkeeping lives on `UVaCuusWorldSubsystem` (it already exists, game-worlds-only), components register/unregister in `OnRegister`/`OnUnregister`.
- Per pointer event: deproject via the local player controller (`GetHitResultAtScreenPosition` on the `"UI"` channel with the per-frame cache pattern, `WidgetComponent.cpp:259-279`) → if the hit component is a registered `UVaCuusWorldComponent`: local-hit math above → `FIntPoint` pixels → `View->SendInput(FVaCuusInputEvent::MouseMove/MouseButton/MouseWheel(...))` — the same constructors the Slate handlers use (`SVaCuusWidget.cpp:404-405,422-424,553`).
- **Consume verdict = the snapshot, same contract as screen-space:** return `true` iff `View->GetSnapshot().Contains(Pixel)` (accessor `VaCuusView.h:500`; scan semantics `VaCuusInteractiveSnapshot.h:495-506`). Pass-through is absence of coverage, exactly as documented (`VaCuusInteractiveSnapshot.h:259-265`).
- **Capture analog:** no Slate capture exists here; latch "buttons down over this panel" in the processor and keep consuming moves/ups until `GetPressedButtons().IsEmpty()` — the same last-button rule the widget uses, with its documented post-release semantics (`SVaCuusWidget.cpp:500-517`).
- **Leave/hover:** when the ray leaves the panel, send `FVaCuusInputEvent::MouseLeave()` — mandatory or `:hover` sticks forever (`SVaCuusWidget.cpp:578-584`).
- **Keys/IME:** keys can be forwarded to a "focused" world panel through the same `KeyEvent` path, but `IInputProcessor` has **no char/text hook** (slate-input.md:619) and world-space hosts are already decided IME-less — decision D17, cited in code (`VaCuusView.cpp:82`). v1 acceptance ("world-space panel interactive via raycast in PIE", spec:401) needs pointer only.
- **VR/motion-controller ray:** an optional `UVaCuusWorldInteraction` source component (X-axis ray à la `WidgetInteractionComponent.cpp:159-176`) feeding the same processor. Not needed for the M5 gate.

Known skew, inherited and accepted: the snapshot is one UI frame stale (`VaCuusInteractiveSnapshot.h:267-273`), and input runs before the frame's poll (`VaCuusView.cpp:664-669`) — identical to screen-space.

## 4. TAA/TSR: the exact preset settings

The shipped preset material (`M_VaCuusWorldPanel`, one asset replacing UMG's six):

- **Blend mode `BLEND_AlphaComposite`** ("AlphaComposite (Premultiplied Alpha)", `EngineTypes.h:252`) — its blend state is `BF_One, BF_InverseSourceAlpha` with the renderer's own comment "New color is already pre-multiplied by alpha" (`TranslucentRendering.cpp:2474-2475`), which is **exactly** the RT's contract: the replay accumulates premultiplied (`VaCuusReplayRenderer.cpp:240-243`) and the screen composite already blends it that way (`VaCuusSlateElement.cpp:122-126`). No `OpacityFromTexture`-style knobs needed.
- **Unlit**, `VaCuusUI` texture parameter = the component RT, Emissive = RGB, Opacity = A.
- **`bEnableResponsiveAA = true`** (`Material.h:544-549`, Translucency category). Mechanism verified end-to-end: it sets `STENCIL_TEMPORAL_RESPONSIVE_AA_MASK` on the translucent draw (`BasePassRendering.cpp:272-287`; bit defined `SceneRenderTargets.h:24,45`) and TAA reads the stencil to cut history (`TemporalAA.usf:2015-2024`; stencil SRV bound at `TemporalAA.cpp:157,703`).
- **TSR ignores it — document that honestly.** `TemporalSuperResolution.cpp` contains no responsive/stencil consumption (the only "responsive" hit is cvar help text at `:125`); its moving-mask input is its own `PF_R8_UINT` slice (`:2439-2478`), not the stencil bit. `bHasPixelAnimation` is the TSR-era flag but is for **opaque** materials (`Material.h:579-583`). So under TSR the mitigation is the spec's other half verbatim: docs recommend post-AA compositing or FXAA for heavy world-space UI (spec:174-176, risk row :366). This matches the spec's framing — mitigation, not cure.
- **Gamma note (new finding, belongs in the preset):** the RT holds display-gamma-encoded pixels — the screen composite goes to the post-tonemap target with "no gamma conversion" (`VaCuusSlateElement.cpp:122-124`) and the RT is created without `TexCreate_SRGB` (`VaCuusReplayRenderer.cpp:166-171`) — but a translucent world material writes into **pre-tonemap linear** scene color. The preset must decode (sRGB→linear on RGB; imperfect on premultiplied data — note it) or the panel reads washed out. `UWidgetComponent` acknowledges the same seam with `bApplyGammaCorrection` (`WidgetComponent.h:533-538`). **Experiment `WS-GAMMA`:** render the M1 HUD on a world panel next to the screen-space composite, A/B the decode node, pick by screenshot parity.
- Two-sided: optional bool on the component, `TwoSided` in the material (`Material.h:559-561`) — UMG ships per-sidedness as separate assets (`WidgetComponent.cpp:656-671`); one material with a static switch is fine. [inference]

## 5. CLI / npm workspace — inventory and deliverable shapes

**Inventory: nothing exists.** No `Web/` directory, no `package.json`, no `.d.ts` in either tree (finds over `/w/Unreal/VcHost/Plugins/VaCuus` and `/w/Unreal/VaCuus` returned zero; top level of the plugin has no `Web/`). The only occurrences of `@vacuus/*` are spec text (spec:46,72-73,261-267,295). Everything below is greenfield against these verified anchor points:

1. **Watch → live reload: works today with one constraint.** The M2 watcher reloads on extensions `rml|rcss|js|mjs` only (`VaCuusLiveReload.cpp:37-40`), recursively under the `Content/DevUI` roots (flags-0 registration, `VaCuusLiveReload.cpp:246-247`; roots `VaCuusContentPaths.cpp:18-43`). So `vacuus dev` (esbuild watch) writing `hud.js` into `<Project>/Content/DevUI/<app>/` triggers a full-document reload with **no plugin changes** — and the reload contract already guarantees fresh script state, because a reload recycles the view's `JSContext` including the module cache (`VaCuusLiveReload.cpp:24-36`). A `.map` sidecar write triggers nothing (not a watched extension) — harmless, and moot with inline maps. Two traps the CLI docs must carry: the watched-roots/inode warning (a bundle written anywhere else produces "no event, no reload and no error", `VaCuusLiveReload.cpp:269-279`) and the debounce (quiet-period flush, `:275-279`), which coalesces esbuild's multi-file writes for free. Note esbuild rebuilds are sub-100 ms while the watcher waits for quiet — latency is dominated by the debounce, which is already tuned.
2. **Typings source of truth: hand-written `.d.ts`, conformance-tested — not generated.** The `vacuus.*` surface is 4 registrations (`emit`, `model`, `stats`, lazy `view` getter — `VaCuusJsHostApi.cpp:95-105`) and the DOM facade is hand-registered `JSCFunctionListEntry` tables (`VaCuusJsDom.cpp:314-339` etc.). Generation from those tables could yield names and arity but **not types** — parameter/return types exist only inside the thunk bodies (e.g. `vacuus.model(name)` returning a fresh `{name, get}` with documented non-identity, `VaCuusJsHostApi.cpp:187-204`). For a surface this small (~40 entries), a hand-written `Web/packages/cli/types/vacuus.d.ts` plus a UI-thread automation test that walks `globalThis.vacuus`/`document`/element prototypes and asserts every typed name exists (and no untyped name does) is cheaper and stays honest by the restore-the-bug standard. [inference] Generation becomes worth revisiting only if the facade grows an IDL.
3. **Sourcemaps: honest v1 = inline maps + raw positions in the overlay.** Stack frames name whatever `JS_Eval` was given: the resolved file path for file scripts, `MakeModuleName(path)` for modules, `<ExecuteScript view N>` for API eval (`VaCuusJsScriptHost.cpp:330-398`, `VaCuusJsViewContext.cpp:224-244`; deterministic name rationale `VaCuusView.cpp:233-236`). The overlay/log captures `Error.stack` — quickjs's `build_backtrace` string (`VaCuusJsRuntime.cpp:406-425`) — so overlay entries already carry `bundle.js:line`. quickjs-ng does not consume sourcemaps; mapping means parsing the map. **v1:** CLI emits `--sourcemap=inline`, overlay prints raw generated positions, CLI ships `vacuus symbolicate <stack>` (node-side, trivial with the `source-map` lib) for offline mapping; in-engine mapping (C++ VLQ decoder or a JS-side `Error.prepareStackTrace`-style hook) is deferred, matching spec Tier-1's "Tier 2 supplies maps" (spec:257-258) without promising in-overlay TSX frames. [inference on the symbolicate subcommand; everything it needs is in the stack string format above]
4. **Workspace shape (Fab constraints are hard requirements):** `Web/` = npm workspace `{packages/preact-vacuus (@vacuus/preact — patched preact + compat over the facade, undom contract), packages/cli (@vacuus/cli — create/dev/build/symbolicate + template + types + base stylesheet + linter rules per spec:365)}` — **source only, no `node_modules`, no binaries**; esbuild/preact fetched on the buyer's machine (spec:48-53); M6's no-executables scan already covers the zip (spec:53).
5. **`@vacuus/preact` risk to spike first:** the facade's `querySelector/appendChild/insertBefore/removeChild/attributes/classList/style/addEventListener/innerRML` set (`VaCuusJsDom.cpp:314-339`, spec:249-251) against preact's actual DOM usage. Precedent accepted by the spec (OneJS, spec:261-263). **Experiment `PREACT-UNDOM`:** run preact's own undom-based test subset (spec:349-350 already plans "JS facade conformance (subset of undom tests)") before patching anything.
