# TASK C — Material decorators: RmlUi surface, recorder/replayer deltas, the UMaterial gate

Path abbreviations: `RmlUi/` = `/w/Unreal/VcHost/Plugins/VaCuus/Source/ThirdParty/RmlUi/`, `Render/` = `/w/Unreal/VcHost/Plugins/VaCuus/Source/VaCuusRender/`, `UE/` = `/w/Unreal/UnrealEngine/Engine/`.

## 1. RmlUi 6 ships `decorator: shader(...)` — the spec's syntax already exists upstream

**It exists and is registered.** `DecoratorShaderInstancer decorator_shader` is a default instancer (`RmlUi/Source/Core/Factory.cpp:91`) registered under the name `"shader"` (`Factory.cpp:202`). So `decorator: shader(glass-panel)` parses today with **zero** RmlUi-side changes. `Factory::RegisterDecoratorInstancer` (`Factory.cpp:456-459`) remains available if we ever want a distinct `material(...)` name, but the spec's `shader("<name-or-asset-path>")` needs nothing registered.

**Parse path.** The `decorator` property parser splits on commas outside parentheses (`RmlUi/Source/Core/PropertyParserDecorator.cpp:55`), looks up the instancer by the text before `(` — unknown type logs `LT_WARNING "Decorator type '%s' not found."` and fails the declaration (`PropertyParserDecorator.cpp:101-106`) — and parses the paren contents against the instancer's own property specification (`:108-118`). A trailing `border-box|padding-box|content-box` keyword selects the paint area (`:11-15`, `:67-88`). The shader instancer declares a single string `value` property with the whole shorthand falling through to it (`RmlUi/Source/Core/DecoratorShader.cpp:69-70`), so the registry key `"glass-panel"` or `"/Game/UI/M_Glass"` arrives verbatim as one string.

**Exactly what crosses the render interface.** All handles are `uintptr_t` (`RmlUi/Include/RmlUi/Core/Types.h:79-82`). The optional-tier virtuals are:

- `CompiledShaderHandle CompileShader(const String& name, const Dictionary& parameters)` — `RmlUi/Include/RmlUi/Core/RenderInterface.h:131`
- `void RenderShader(shader, geometry, Vector2f translation, TextureHandle texture)` — `RenderInterface.h:137`
- `void ReleaseShader(shader)` — `RenderInterface.h:140`

Per-decorator dictionaries, opened and read:

| RCSS | `CompileShader` name | Dictionary | cite |
|---|---|---|---|
| `shader(x)` | `"shader"` | `value`:String, `dimensions`:Vector2f | `DecoratorShader.cpp:35` |
| `linear-gradient` | `"linear-gradient"` | `p0`,`p1`:Vector2f, `length`:float, `repeating`:bool, `color_stop_list`:ColorStopList | `DecoratorGradient.cpp:252-259` |
| `radial-gradient` | `"radial-gradient"` | `center`,`radius`:Vector2f, `repeating`, `color_stop_list` | `DecoratorGradient.cpp:422-428` |
| `conic-gradient` | `"conic-gradient"` | `angle`:float, `center`:Vector2f, `repeating`, `color_stop_list` | `DecoratorGradient.cpp:619-625` |

`ColorStop` = premultiplied colour + `NumericValue` position (`RmlUi/Include/RmlUi/Core/DecorationTypes.h:8-11`; list type `Types.h:120`); `Variant` natively carries `VECTOR2` and `COLORSTOPLIST` (`Variant.h:33,45`) — everything is plain data, trivially serializable into the command buffer.

**Lifecycle.** `DecoratorShader::GenerateElementData` compiles the shader, builds a background mesh with UVs normalised to the paint box, and pools `{Geometry, CompiledShader}` (`DecoratorShader.cpp:27-53`); `RenderElement` calls `geometry.Render(offset, {}, shader)` (`:61-65`), which `RenderManager::Render` dispatches to `RenderShader(...)` instead of `RenderGeometry(...)` when a shader is present (`RenderManager.cpp:234-237`) — **same translation/texture/scissor/transform state as any other draw**. Release rides `RenderManager::ReleaseResource → ReleaseShader` (`RenderManager.cpp:364-368`). The whole compile happens *inside element render* — `RenderEffects → ReloadEffectsData → GenerateElementData` (`RmlUi/Source/Core/Element.cpp:194-211`, `ElementEffects.cpp:185-188`, `:140`) — i.e. inside the recorder's open frame, so a shader is always created in the same buffer that first draws with it, which the replayer contract already supports (`Render/Public/VaCuusReplayRenderer.h:23-25`). An animated gradient re-runs `GenerateElementData` (release + fresh `CompileShader`) — resource traffic every change, which is exactly what wakes the idle gate.

**What failure looks like today.** `CompileShader`'s default returns `{}` (`RmlUi/Source/Core/RenderInterface.cpp:54-57`), `RenderManager::CompileShader` forwards the zero (`RenderManager.cpp:285-294`), the decorator returns `INVALID_DECORATORDATAHANDLE` (`DecoratorShader.cpp:36-37`), which by contract suppresses rendering (`Decorator.h:42-44`), and RmlUi logs one `LT_WARNING "Could not generate decorator element data: <element>"` (`ElementEffects.cpp:150-151`). So today `decorator: shader(...)`, `linear/radial/conic-gradient` draw **nothing**, with one warning per element.

## 2. The recorder today, and what recording shaders costs

The recorder overrides exactly 9 of the 21 virtuals — geometry trio, texture trio, scissor pair, transform (`Render/Private/VaCuusRecordingRenderInterface.h:109-117`). The shader trio is at its defaults, and the command-buffer header already names this as the known gap: *"a document with an animated gradient whose NewShaders map went unnamed here would publish frame one and then freeze"* (`Render/Public/VaCuusCommandBuffer.h:197-204`).

The M3 memory is enforced by shape, and adding shaders trips every tripwire on purpose:

- **New resource arrays** `NewShaders : TMap<handle, FVaCuusShaderDesc>` + `ReleasedShaders : TArray<handle>` on `FVaCuusCommandBuffer` → the seven-member count (`VaCuusCommandBuffer.h:215-217`) fails the build inside `HasResourceTraffic()` (`:233-237`) until both are added to the predicate (`:239-240`) and the count is bumped to nine. The idle-gate predicate lives next to the arrays it tests — the header was written for this exact edit.
- **New command** `DrawShader` (enum `:19-25`) plus a `Shader` handle field on `FVaCuusCommand` (`:28-46`) → the six-member count (`:97-99`, asserted at `:379-381`) and the `sizeof==112`/offset asserts (`:382-387`) fail until `FVaCuusCommandHashImage` (`:261-269`) gains a `Shader` slot and its no-padding assert (`:271-273`) is updated. An unhashed shader handle would be a frame change the gate can't see — the tripwires exist because of that failure mode.
- **Recorder** mints shader handles like geometry ones (strictly increasing, never recycled — `VaCuusRecordingRenderInterface.cpp:140-141` is the pattern); `CompileShader` converts the `Dictionary` (5 Variant kinds, above) into a POD desc; `ReleaseShader` appends to `ReleasedShaders`. Out-of-frame resource calls are already legal (`VaCuusRecordingRenderInterface.h:89-94`); `RenderShader` outside a frame is a caller bug like `RenderGeometry`.
- **Replayer** grows a `Shaders` map beside `Geometry`/`Textures` (`VaCuusReplayRenderer.h:111-112`), uploads/retires it in `UploadNewResources`/`RetireBufferResources`, and adds a `DrawShader` case to the switch (`VaCuusReplayRenderer.cpp:256-353`). Today the whole pass is one PSO — `FVaCuusUIVS`/`FVaCuusUIPS` bound once before the loop (`:227-250`) — so `DrawShader` is the first command that switches PSO mid-pass; scissor/transform state carries across because it is command-buffer state, not PSO state.

**These deltas are needed for the fallback tier too** — gradients cross the same three virtuals. The material gate only decides what a `DrawShader` whose desc names a `/Game/` path does.

## 3. The UMaterial half — what the spike must answer, with the engine's own precedents

**How Slate draws a material brush** (`UE/Source/Runtime/SlateRHIRenderer/Private/SlateRHIRenderingPolicy.cpp:1122-1202`): take `FMaterialRenderProxy` (`:1133`), walk `UpdateUniformExpressionCacheIfNeeded → Material->TryGetShaders(ShaderTypesToGet, nullptr, Shaders)` with fallback-proxy loop (`:1157-1170`), bind vertex+pixel material shaders with a **view uniform buffer** and `FMaterialShader::GetShaderBindings` (`SlateMaterialShader.cpp:34-46`, `:74-90`), pick blend state from the material (`:1202`). The shader types are `FMaterialShader` subclasses compiled **only for `MaterialDomain == MD_UI`** (`SlateMaterialShader.cpp:31`, `:50`) against engine shader files (`:111-132`). What a UI material *is* at the shader level: `Emissive` = colour, `Opacity` = alpha (`UE/Shaders/Private/SlateElementPixelShader.usf:245-246`).

**Is Slate's path reachable from our pass? Not directly.** `FSlateMaterialShaderVS/PS` are declared in a private header with no export macro (`SlateMaterialShader.h:14`, `:33`) — VaCuusRender cannot name those types, and without the type you cannot call their parameter setters. But **nothing about the mechanism is Slate-private**:

1. **A plugin can define its own material shader types.** Engine precedent: TextureGraph declares `FTextureGraphMaterialShaderVS/PS : FMaterialShader` with `DECLARE_SHADER_TYPE(..., Material)` (`UE/Plugins/TextureGraph/Source/TextureGraphEngine/FxMat/FxMaterial_DrawMaterial.h:27-97`), implemented against a **plugin** `.usf` via `IMPLEMENT_MATERIAL_SHADER_TYPE` (`FxMaterial_DrawMaterial.cpp:10-11`), and draws an arbitrary `UMaterialInterface` as a screen quad in its own pass. Its `.usf` shows the whole recipe for evaluating a material in a hand-rolled quad PS: `#include "/Engine/Generated/Material.ush"`, `MakeInitializedMaterialPixelParameters`, `CalcMaterialParametersPost`, `GetMaterialEmissive/GetMaterialOpacity` (`UE/Plugins/TextureGraph/Shaders/TextureGraphMaterialShader.usf:8-10, 44-74`). VaCuusRender already maps `/Plugin/VaCuus` shaders (`Render/Private/VaCuusRender.cpp:1823`) and loads at `PostConfigInit` (`/w/Unreal/VcHost/Plugins/VaCuus/VaCuus.uplugin`, VaCuusRender module entry) — early enough to register shader types.
2. **Parameter binding fits our existing draw loop.** `FMaterialShader::SetParameters(FRHIBatchedShaderParameters&, const FMaterialRenderProxy*, const FMaterial&, const FSceneInterface* Scene)` exists (`UE/Source/Runtime/Renderer/Public/MaterialShader.h:88-92`) — batched-parameters based, `FSceneView`-free; the replayer already uses `GetScratchShaderParameters`/`SetBatchedShaderParameters` per draw (`VaCuusReplayRenderer.cpp:310-317`).
3. **The view uniform buffer can be fabricated without a scene or an FSceneView.** Slate itself does exactly that: `FViewUniformShaderParameters` filled by the free, `ENGINE_API` `SetupCommonViewUniformBufferParameters` from nothing but a viewrect, an ortho `FViewMatrices`, and show flags, then `CreateUniformBufferImmediate` (`SlateRHIRenderingPolicy.cpp:706-756`; free-function declaration `UE/Source/Runtime/Engine/Public/SceneView.h:2840`, inputs struct `:2787`). One UB per replay pass, not per draw.

**The wrong path, named so nobody proposes it:** `IRendererModule::DrawTileMesh` (`UE/Source/Runtime/RenderCore/Public/RendererInterface.h:280`) is the Canvas material-tile route, but it spins up an `FViewInfo`, scene uniform buffers, dummy forward-light/shadow/fog buffers and a full mesh-pass processor **per tile** (`UE/Source/Runtime/Renderer/Private/Renderer.cpp:473-570`) — and it feeds mesh passes, which filter by domain (`ShouldIncludeDomainInMeshPass`, `BasePassRendering.cpp:2339`; UI materials explicitly skipped for base-pass PSOs at `:2347-2351`). [inference] MD_UI materials compile no base-pass mesh shaders at all, so `DrawTileMesh` cannot draw them; it is for surface-domain Canvas tiles.

**Honest constraints the spike must respect** (these are the GO/NO-GO facts, not implementation niceties):

- **Blend/gamma contract.** Our RT accumulates premultiplied alpha with `One/InverseSourceAlpha` (`VaCuusReplayRenderer.cpp:240-243`) and the composite assumes it (`Render/Private/VaCuusSlateElement.cpp:122-126`). A UI material's Emissive/Opacity is straight alpha; Slate picks blend state per material blend mode (`SlateRHIRenderingPolicy.cpp:1202`). Our PS must premultiply on output and we must map Opaque/Masked/Translucent/Additive onto the premultiplied RT. Solvable in the shader; must be *verified over text* in the spike.
- **Shader-map cost.** Two new material shader types gated on MD_UI mean every UI-domain material in the project compiles two more permutations, and DDC invalidation for them the first time the plugin is present. Scoped, but it is a real per-project cost the gate decision should record.
- **No scene textures.** Custom-stencil/scene-texture nodes in a UI material will not work in our pass (TextureGraph rejects such maps explicitly — `FxMaterial_DrawMaterial.cpp:145-162`; Slate needs `BufferToSceneTextureScale` hacks even in-engine, `SlateRHIRenderingPolicy.cpp:744-745`). Registry validation should reject them with a named error.
- **Raw-RHI vs RDG.** Replay runs raw RHI inside a `SkipRenderPass` RDG pass (`VaCuusSlateElement.cpp:70-84`). `UpdateUniformExpressionCacheIfNeeded` and per-draw batched binds are RHI-level and fit; anything demanding RDG-registered resources (VT feedback) is out of scope for v1 — declare virtual-texture-sampling UI materials unsupported.

## 4. The registry surface: what exists today, and the thread handoff

Today: `CanContainContent: true` (`VaCuus.uplugin`, line `"CanContainContent": true`), but `Content/` holds only `DevUI/*.rml|rcss|js` text (listing of `/w/Unreal/VcHost/Plugins/VaCuus/Content/DevUI/`), **no `.uasset`, no UObject asset type anywhere** — the plugin's only UCLASSes are subsystems, the view, and the world subsystem (`Source/VaCuus/Public/VaCuusSubsystem.h:45`, `VaCuusView.h:118-119`, `VaCuusWorldSubsystem.h:13`); grep for `StyleSet` over plugin sources returns nothing. `UVaCuusStyleSet` is a green-field M5 asset (spec `docs/superpowers/specs/2026-07-29-vacuus-architecture-design.md:184-190`).

**Thread rule and handoff.** `InstanceDecorator` and `CompileShader` both run on the UI thread (all RmlUi calls do — recorder contract `VaCuusRecordingRenderInterface.h:82-94`; compile site §1 above), and module resolution off the game thread is a known hard crash class (`VaCuusRecordingRenderInterface.h:177-184`) — a fortiori no `LoadObject` there. Sketch:

1. **Game thread, ahead of time:** `UVaCuusStyleSet` (preloaded/cooked) maps `FString key → UMaterialInterface*` (+ builtin names). On registration the subsystem roots each material (`TStrongObjectPtr`), calls `GetRenderProxy()` once, and publishes an immutable snapshot table `key → {EKind::Builtin|Material, StableId}` to the UI thread through the existing command queue (same channel views already use).
2. **UI thread:** recorder's `CompileShader("shader", {value,...})` is a pure lookup in that snapshot → mints a handle, records `FVaCuusShaderDesc {Kind, StableId or BuiltinParams}`. Unknown key → return 0, RmlUi logs the element warning (§1) — the correct RCSS-error behaviour for free.
3. **Render thread:** replayer resolves `StableId → FMaterialRenderProxy*` from a render-thread mirror updated by the same subsystem (enqueued via `ENQUEUE_RENDER_COMMAND` on registration/unregistration; unregistration must fence on views that still hold draws, mirroring the deferred-release discipline of `ReleasedTextures`, `VaCuusCommandBuffer.h:184-185`). RCSS-fed per-draw parameters ride in the desc; per-material dynamic parameters are game-side MIDs, which is UE-native anyway.

## 5. The fallback line: what RmlUi ships and what already works today

Registered built-ins (`Factory.cpp:195-213`): `text`, `tiled-horizontal`, `tiled-vertical`, `tiled-box`, `image`, `ninepatch`, `shader`, `gradient`/`horizontal-gradient`/`vertical-gradient`, `linear-gradient`(+repeating), `radial-gradient`(+repeating), `conic-gradient`(+repeating).

- **Record/replay correctly today (geometry+texture only):** `image`/`tiled-*` (`DecoratorTiledBox.cpp:227`, `DecoratorTiledHorizontal.cpp:115`), `ninepatch` (`DecoratorNinePatch.cpp:153`), `text` (`DecoratorText.cpp:52`), and the legacy straight `gradient` family — per-vertex colours, no shader (`DecoratorGradient.cpp:136-184`).
- **Silently absent today (need the §2 deltas + one replayer PS each):** `shader`, `linear/radial/conic-gradient`. The fallback tier = implement these as permutations/parameter modes of a new global gradient PS beside `FVaCuusUIPS` (`Render/Private/VaCuusUIShaders.h:26-46`, `Shaders/Private/VaCuusUI.usf`), plus a small builtin set behind `shader(<name>)`. Note `blur`/`drop-shadow`/masks are the **filter** trio + layer stack (`RenderInterface.h:98-125`) — a separate, larger contract shared with Task B's backdrop-filter; do not let the gate decision smuggle it in.

## 6. The spike protocol (2 days, per spec §5/§13)

**Build (throwaway branch, VcHost clone):**
1. *Day 1 — draw one material at all.* `FVaCuusMaterialVS/PS : FMaterialShader`, `ShouldCompilePermutation = (MaterialDomain == MD_UI)` (pattern: `SlateMaterialShader.cpp:29-32`), `/Plugin/VaCuus/VaCuusMaterial.usf` modeled on `TextureGraphMaterialShader.usf:24-74` but outputting `float4(Emissive*Opacity, Opacity)` (premultiplied). In the replay pass: synthetic view UB via `SetupCommonViewUniformBufferParameters` (`SceneView.h:2840`, recipe `SlateRHIRenderingPolicy.cpp:706-756`), `TryGetShaders` with the fallback-proxy walk (`SlateRHIRenderingPolicy.cpp:1157-1170`), PSO switch on our existing vertex declaration, hardcoded proxy from a test material. Skip the recorder: inject a synthetic `DrawShader` after replay.
2. *Day 2 — the contract, not more features.* (a) blend-mode matrix: Translucent/Additive/Opaque UI material over text on the RT — premultiplied compositing must hold; (b) scalar + texture parameter driven per-frame through an MID — proxy picks up the change in our pass without a Slate draw anywhere; (c) idle-gate interaction — static material quad must not force publishes (material animation is GPU-side; the *recorded* frame is unchanged — confirm the RT still updates every engine frame because the **composite** reruns even when replay is withheld, `VaCuusSlateElement.cpp:91-140`)… and record the counter-finding if a time-animated material *does* freeze because replay is skipped — that is a real architectural finding the gate decision must state (the fix — composite-time material draw or forced republish while a material decorator is live — changes the cost of GO); (d) RHI check on Vulkan + a `-game` monolithic build (per CLAUDE.md, different code path).

**GO** = all of: material quad renders in the replay RT with correct premultiplied blending over UI content; per-draw parameters land without game-thread hitching; no per-frame uniform-expression or PSO cost that moves the Record/Replay perf scope beyond noise; the idle-gate finding has an acceptable answer. **FALLBACK** (spec `…design.md:189-190`, `:363`) = any of those fails or exceeds the 2 days: ship gradients + builtin `shader(<name>)` global-shader set only; §1 marketing promise downgraded; the recorder/replayer shader plumbing (§2) ships regardless, so the material tier can return in v1.x without a format break.

**Either way, record the decision** with: the blend-matrix screenshots, the idle-gate finding, and the measured added cost of `UpdateUniformExpressionCacheIfNeeded` per material per frame.
